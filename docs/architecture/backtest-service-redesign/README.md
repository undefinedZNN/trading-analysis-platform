## 🎯 设计目标

### 核心问题
当前系统在处理大规模数据（如 6 个月的 1 秒级数据，约 1580 万条）时遇到内存溢出问题。

### 设计目标
1. **内存可控**：支持任意规模数据集，内存占用可预测且可控（< 500 MB）
2. **服务隔离**：回测执行与主服务隔离，互不影响
3. **高性能**：保持高吞吐量（> 10K bars/sec）
4. **可扩展**：支持多实例部署，水平扩展

## 💡 核心方案

### 1. 服务隔离
- ✅ 独立的回测执行服务
- ✅ HTTP 通信（无需容器化）
- ✅ 服务注册机制

### 2. 数据处理
- ✅ 滑动窗口 + 流式加载（批次大小：20K）
- ✅ 内存逐步销毁
- ✅ 按需从 DuckDB 读取（兜底方案）

### 3. 多时间框架
- ✅ 数据集预先聚合多个时间级别
- ✅ 策略按需选择时间框架

## 📝 设计原则

1. **简单优先**：使用 HTTP 而非复杂的消息队列
2. **渐进式**：分阶段实施，每个阶段都可独立验证
3. **向后兼容**：保持现有 API 不变
4. **可观测性**：完善的日志、监控、指标
