## 🎯 详细决策说明

### 第一部分：可视化系统

#### 1. K 线图 ✅
**决策**: B+（增强简化版）

**需求说明**：
- ✅ K 线图（OHLC）
- ✅ 成交量柱状图
- ✅ 标注所有交易点位（支持多次加仓、多次减仓）
  - 首次建仓、加仓、减仓、止盈、止损、打平需清晰区分
- ❌ 不需要技术指标叠加（MA、RSI、MACD 等）

**关键要求**：
- 一个策略可能会触发多次加仓入场
- 也可能出现多次分批止盈、止损、打平
- 每个交易点位都需要清晰标注

#### 2. 报告导出格式 ✅
**决策**: 不需要导出

- 用户只在前端页面查看
- 用户可以通过过滤交易因子生成多份不同视图的报告
- 前端实时应用过滤器，动态生成统计结果

#### 3-5. 其他可视化决策 ✅
- 自定义模板：不需要
- 实时更新：不需要（回测完成后再显示）
- 数据量处理：混合方式

---

### 第二部分：回测数据缓存

#### 6. 是否需要缓存 ✅
**决策**: B（POC 阶段就加缓存）

- POC 阶段就实现内存缓存
- 特别适用于参数优化场景

#### 7. 缓存容量限制 ✅
**决策**: B（默认 2GB，可配置）

```yaml
cache:
  enabled: true
  type: memory
  memory:
    capacity_mb: 2048  # 可配置
    eviction_policy: lru
```

#### 8-10. 其他缓存决策 ✅
- 缓存预热：不需要（按需加载）
- 失效策略：LRU + Worker 重启时清空
- Redis：不需要（先用内存缓存）

---

### 第三部分：策略版本管理

#### 11. 版本编辑行为 ✅
**决策**: B（每次编辑创建新版本）

**重要变更**：
- 现有的 `updateScriptVersion` 需要修改行为
- 从 UPDATE 操作变为 INSERT 新版本
- 保留所有历史版本，永不覆盖

**实现示例**：
```typescript
async updateScriptVersion(strategyId, scriptVersionId, dto) {
  const oldVersion = await this.scriptVersionRepository.findOne({
    where: { scriptVersionId, strategyId }
  });
  
  // 不再更新现有版本，而是创建新版本
  const newVersion = await this.createVersionInternal(strategyId, {
    code: dto.code ?? oldVersion.code,
    remark: dto.remark, // 必填
    versionName: generateVersionName(existingVersions),
    createdBy: dto.updatedBy
  }, false);
  
  return newVersion;
}
```

#### 12. 版本说明必填 ✅
**决策**: B（必填）

每次创建新版本时，必须填写 `remark` 字段。

#### 13. 版本回滚方式 ✅
**决策**: A（切换 master）

```typescript
// 回滚到 v2
await setMasterVersion(strategyId, v2ScriptVersionId);
// 结果：v2.is_master = true, v3.is_master = false
```

#### 14-16. 其他版本管理决策 ✅
- 版本删除：不允许删除
- 版本标签：现有实现已覆盖
- 版本命名：现有实现已覆盖

### 第四部分：异常恢复

#### 17. 自动重试策略 ✅
**决策**: A（不自动重试）

- 任务失败后不自动重试
- 用户需要手动重新提交

#### 18-19. 断点续跑 ✅
**决策**: B（需要），C（按K线数）

- 支持断点续跑功能
- 每处理 1000 根 K 线保存一次 Checkpoint

**Checkpoint 包含**：
- 账户状态
- 持仓信息
- 已执行交易
- 数据索引

#### 20. 任务失败后的数据处理 ✅
**决策**: B（保留部分结果）

- 保留已计算的交易数据和 Checkpoint
- 便于问题排查和调试

#### 21. 告警通知方式 ✅
**决策**: 站内消息

| 级别 | 场景 | 通知对象 | 通知方式 |
|------|------|---------|---------|
| INFO | 任务开始、完成 | 用户 | 站内消息 |
| WARNING | Worker 心跳超时 | 管理员 | 站内消息 |
| ERROR | 任务失败、Worker 崩溃 | 用户 + 管理员 | 站内消息 |

#### 22. Worker 健康检查 ✅
**决策**: A（只检查心跳）

- Worker 定期发送心跳（30秒一次）
- Backend 检测心跳超时（60秒）
- 超时后标记 Worker 为离线
