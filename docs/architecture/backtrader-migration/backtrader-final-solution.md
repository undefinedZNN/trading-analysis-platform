# Backtrader 完全替换方案 - 最终方案

**决策时间**: 2025-11-20  
**核心决策**: 
- ✅ 改用 Python 策略（完全放弃 TypeScript 动态策略）
- ✅ 完全下线自研回测引擎
- ✅ 全面使用 Backtrader

---

## 📋 核心决策确认

### ✅ 已确认的决策

1. **动态策略**: 改用 Python 策略
   - 用户必须用 Python 编写策略
   - 现有 TypeScript 策略全部清空（不迁移）
   - 前端提供 Python 代码编辑器

2. **自研引擎**: 完全下线
   - 删除所有 TypeScript 回测引擎代码
   - 不保留作为备份
   - 彻底迁移到 Backtrader

3. **通信方式**: RabbitMQ
   - NestJS → RabbitMQ → Python Worker
   - 利用现有 RabbitMQ 基础设施
   - 异步解耦，可水平扩展

4. **因子系统**: 统一插件
   - 开发统一的因子收集插件
   - 所有策略共用
   - 便于维护和扩展

5. **数据格式**: 继续 Parquet
   - 不需要迁移历史数据
   - Python PyArrow 支持良好
   - 实现 Backtrader DataFeed 适配器

6. **前端编辑器**: Monaco Editor
   - VS Code 内核
   - 语法高亮、代码补全、错误提示
   - 提供完整的 IDE 体验

7. **部署方式**: 微服务架构
   - NestJS Backend + Python Worker 独立部署
   - 解耦合、可独立扩展

8. **策略迁移**: 不迁移，直接清空
   - ❌ 不开发迁移工具
   - 🗑️ 直接清空现有策略数据
   - 🆕 用户用 Python 从零开始

## 🗂️ 数据流设计

### 1. 创建回测任务

```
用户操作:
1. 在前端编写 Python 策略代码
2. 选择数据集
3. 配置参数
4. 提交任务

数据流:
Frontend → NestJS API
  ↓
NestJS 保存策略和任务
  ↓
发布消息到 RabbitMQ: backtest.task
  {
    task_id: "xxx",
    strategy_code: "...",  // Python 代码
    data_path: "/data/datasets/xxx.parquet",
    parameters: {...}
  }
```

### 2. 执行回测

```
Python Worker:
1. 从 RabbitMQ 消费任务
2. 编译 Python 策略代码
3. 加载 Parquet 数据
4. 运行 Backtrader
5. 收集结果

进度更新:
Worker → RabbitMQ: backtest.progress
  {
    task_id: "xxx",
    progress: 0.45,
    processed_bars: 450,
    total_bars: 1000
  }
  ↓
NestJS 消费进度
  ↓
Frontend 轮询或 WebSocket 更新
```

### 3. 结果处理

```
Worker 完成:
1. 保存交易记录到 Parquet
2. 保存因子数据到 Parquet
3. 发布结果消息

Result Message:
Worker → RabbitMQ: backtest.result
  {
    task_id: "xxx",
    status: "completed",
    metrics: {...},
    trades_file: "/data/backtests/xxx/trades.parquet",
    factors_file: "/data/backtests/xxx/factors.parquet"
  }
  ↓
NestJS 消费结果
  ↓
更新任务状态
  ↓
Frontend 显示结果
```
