# 创建回测任务 - 两种场景验证指南

**创建日期**: 2025-11-13  
**修复版本**: v2.0  
**测试目的**: 验证两种创建场景是否正常工作

---

## 🎯 测试目标

验证 `CreateBacktestTaskModal` 组件在两种场景下的正确性：

1. **场景1**: 从策略列表/详情页创建（策略ID已知）
2. **场景2**: 从任务列表页创建（需要选择策略）

---

## 📋 测试前准备

### 1. 启动服务

```bash
# 终端1：启动后端
cd backend
npm run start:dev

# 终端2：启动前端
cd frontend
npm run dev
```

### 2. 准备测试数据

#### 创建一个测试策略

1. 访问 `http://localhost:5173/backtesting/strategies`
2. 点击"创建策略"
3. 填写表单：
   - 策略名称：`测试双均线策略`
   - 描述：`用于验证创建任务功能`
   - 标签：`test`, `验证`
4. 脚本内容：
```typescript
import { defineStrategy } from '@platform/backtesting-sdk';

export default defineStrategy({
  parameters: [
    {
      key: 'fastPeriod',
      label: '快线周期',
      type: 'number',
      component: 'number',
      defaultValue: 12,
      required: true,
    },
    {
      key: 'slowPeriod',
      label: '慢线周期',
      type: 'number',
      component: 'number',
      defaultValue: 26,
      required: true,
    },
  ],
  factors: [],
  run(ctx) {
    // TODO: implement strategy logic
  },
});
```
5. 点击"创建"

#### 导入一个测试数据集

1. 访问 `http://localhost:5173/trading-data/datasets`
2. 点击"导入数据集"
3. 上传CSV文件或使用示例数据
4. 等待导入完成

## 🧪 场景1测试：从策略列表创建

### 测试步骤

1. **进入策略列表页**
   - URL: `http://localhost:5173/backtesting/strategies`
   - 确认可以看到刚才创建的"测试双均线策略"

2. **点击"开始回测"按钮**
   - 找到策略卡片/行
   - 点击"开始回测"或"创建任务"按钮

3. **验证模态框内容**

   检查清单：
   - [ ] 模态框正常打开
   - [ ] **策略名称字段**：
     - [ ] 显示为只读输入框（灰色背景）
     - [ ] 显示值为"测试双均线策略"
     - [ ] 无法编辑
   - [ ] **脚本版本字段**：
     - [ ] 下拉框正常显示
     - [ ] 默认选中 `v1.0 [Master]`
     - [ ] 可以切换到其他版本（如果有）
   - [ ] **策略参数区域**：
     - [ ] 显示"策略参数"标题
     - [ ] 自动渲染"快线周期"和"慢线周期"字段
     - [ ] 默认值分别为 12 和 26

4. **填写其他字段**
   - 任务名称：可以使用"自动生成"
   - 数据集：选择刚才导入的数据集
   - 时间范围：使用默认值或修改
   - 初始资金：保持默认10000或修改

5. **提交表单**
   - 点击"创建任务"
   - [ ] 没有验证错误
   - [ ] 看到"回测任务创建成功！"提示
   - [ ] 模态框自动关闭

6. **验证结果**
   - 跳转到任务列表或刷新页面
   - [ ] 新创建的任务出现在列表中
   - [ ] 任务状态为"待执行"

### 预期结果

✅ **策略名称只读显示**，不需要用户选择  
✅ **默认选中master版本**，用户可以切换  
✅ **参数自动渲染**，显示正确的默认值  
✅ **提交成功**，任务创建成功

## 🐛 常见问题排查

### 问题1：场景1中策略名称字段可编辑

**现象**: 策略名称输入框不是灰色，可以输入文字

**排查**:
1. 检查组件代码中 `isScenario1` 判断
2. 确认 `Input` 组件有 `disabled` 属性

**修复**: 
```tsx
{isScenario1 && strategy && (
  <Form.Item label="策略名称">
    <Input value={strategy.name} disabled />  {/* ← 必须有 disabled */}
  </Form.Item>
)}
```

### 问题2：场景2没有策略选择框

**现象**: 任务列表页创建任务时，直接显示版本选择，没有策略选择

**排查**:
1. 检查 `BacktestTaskListPage.tsx` 中调用 `CreateBacktestTaskModal` 时是否传了 `strategyId`
2. 确认组件内部 `isScenario2` 判断

**修复**:
```tsx
// BacktestTaskListPage.tsx
<CreateBacktestTaskModal
  open={createModalOpen}
  onCancel={() => setCreateModalOpen(false)}
  onSuccess={handleSuccess}
  // strategyId 不能传，留空！
  datasets={datasets}
/>
```

### 问题3：选择策略后版本字段仍然禁用

**现象**: 场景2选择策略后，版本下拉框还是灰色，无法选择

**排查**:
1. 检查 `handleStrategyChange` 是否正确设置 `selectedStrategyId`
2. 确认 `useEffect` 是否正确加载策略详情
3. 检查版本选择框的 `disabled` 条件

**修复**:
```tsx
<Select
  disabled={!strategy}  // ← 应该根据 strategy 是否加载来判断
  ...
/>
```

### 问题4：参数没有自动渲染

**现象**: 选择版本后，策略参数区域没有显示

**排查**:
1. 检查策略脚本的 `parameters` 定义
2. 确认 `parameterSchema` 状态是否正确更新
3. 查看控制台是否有错误

**修复**:
- 确保策略脚本包含 `parameters` 数组
- 确保 `parameterSchema` 正确传递给 `DynamicParamsForm`
