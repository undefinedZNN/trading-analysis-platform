# 策略测试结果验证指南

## 概述

本文档说明如何验证策略测试结果的准确性，确保账户盈亏计算、交易记录和资金流动都是正确的。

## 验证机制

### 1. 简单验证测试

我们首先运行一个简单的、可手工验证的测试用例：

```bash
npx tsx src/backtesting/strategies/test-strategies.ts
```

**简单验证测试场景**：
- 初始资金: $10,000
- 场景 1: 买入 0.1 BTC @ $50,000 → 成本 $5,000
- 场景 2: 价格上涨到 $55,000 → 未实现盈利 $500
- 场景 3: 卖出 0.05 BTC @ $55,000 → 已实现盈利 $250
- 场景 4: 价格跌到 $52,000 → 剩余持仓价值变化
- 场景 5: 全部卖出 @ $52,000 → 再实现盈利 $100

**预期最终结果**：
- 现金: $10,350
- 持仓: 0 BTC
- 总盈亏: +$350
- 已实现盈亏: $350

### 2. 自动验证检查

每个策略测试结束后，系统会自动执行以下验证：

#### ✅ 验证项 1: 权益计算正确性

**验证公式**：
```
权益 = 现金 + 持仓价值
```

确保当前权益等于现金加上持仓的市场价值。

#### ✅ 验证项 2: 资金守恒

**验证公式**：
```
初始资金 + 总收入 = 当前现金 + 总成本
```

- **总收入**：所有卖出交易的收入总和
- **总成本**：所有买入交易的成本总和

这确保了资金没有凭空消失或产生。

> **注意**：由于浮点数精度问题，允许 ±$0.15 的微小误差。

#### ✅ 验证项 3: 持仓数量一致性

**验证公式**：
```
当前持仓 = 累计买入数量 - 累计卖出数量
```

确保交易记录中的买卖数量与账户持仓匹配。

#### ✅ 验证项 4: 卖出不超过买入

**验证规则**：
```
累计卖出数量 ≤ 累计买入数量
```

防止出现"卖空"或无持仓卖出的错误。

#### ✅ 验证项 5: 账户状态合理性

**验证规则**：
- 现金 ≥ 0（不能为负）
- 持仓 ≥ 0（不能为负）

## 如何手工验证测试结果

### 步骤 1: 运行测试

```bash
cd backend
npx tsx src/backtesting/strategies/test-strategies.ts
```

### 步骤 2: 检查简单验证测试

查找输出中的 "简单验证测试" 部分，确保显示：

```
✅ 简单验证测试通过！
```

如果失败，会显示具体的错误信息。

### 步骤 3: 检查策略测试验证

每个策略测试结束后会显示：

```
✅ 账户状态验证:
----------------------------------------------------------------------
✅ 所有验证通过
  ✓ 资金守恒正确
  ✓ 交易记录一致
  ✓ 持仓计算准确
  ✓ 账户状态合理
```

### 步骤 4: 手工抽查交易详情

从输出中选择几笔交易进行手工验证：

**买入交易验证**：
- 检查 `成本 = 数量 × 价格`

**卖出交易验证**：
- 检查 `收入 = 数量 × 价格`
- 检查 `盈亏 = 数量 × (卖出价 - 买入价)`
- 检查 `盈亏百分比 = 盈亏 / 买入价 × 100%`

### 步骤 5: 验证总体指标

**验证公式**：

1. **胜率计算**：
   ```
   胜率 = 盈利交易数 / (盈利交易数 + 亏损交易数) × 100%
   ```

2. **平均盈利/亏损**：
   ```
   平均盈利 = 所有盈利交易的盈亏总和 / 盈利交易数
   平均亏损 = 所有亏损交易的盈亏总和 / 亏损交易数（取绝对值）
   ```

3. **盈亏比**：
   ```
   盈亏比 = 平均盈利 / 平均亏损
   ```

4. **总盈亏验证**：
   ```
   总盈亏 = 最终权益 - 初始资金
   总盈亏百分比 = 总盈亏 / 初始资金 × 100%
   ```

## 示例：手工验证一个完整的交易序列

假设以下交易序列（初始资金 $10,000）：

```
1. 买入 0.1 BTC @ $50,000
   → 成本: 0.1 × 50,000 = $5,000
   → 现金: $10,000 - $5,000 = $5,000
   → 持仓: 0.1 BTC

2. 卖出 0.1 BTC @ $55,000
   → 收入: 0.1 × 55,000 = $5,500
   → 盈亏: 0.1 × (55,000 - 50,000) = $500
   → 现金: $5,000 + $5,500 = $10,500
   → 持仓: 0 BTC
   → 总权益: $10,500

验证资金守恒:
  初始 + 收入 = 现金 + 成本
  $10,000 + $5,500 = $10,500 + $5,000
  $15,500 = $15,500 ✓
```

## 常见问题

### Q: 为什么会有 $0.10 以内的误差？

**A**: 由于以下原因可能产生微小的浮点数精度误差：
- JavaScript 的浮点数计算精度限制
- 多次小数运算的累积误差
- 价格和数量的四舍五入

系统设定了 $0.15 的容差阈值来处理这种正常误差。

### Q: 如何判断测试结果是否可信？

**A**: 如果满足以下条件，测试结果可信：
1. ✅ 简单验证测试通过
2. ✅ 所有策略的账户状态验证都通过
3. ✅ 手工抽查的交易计算正确
4. ✅ 总体指标计算合理（如胜率、盈亏比等）

### Q: 发现验证失败怎么办？

**A**: 检查以下几点：
1. 查看具体的错误信息
2. 检查是否超过了允许的误差范围（>$0.15）
3. 确认交易逻辑是否正确
4. 检查是否有数据异常（如负现金、负持仓）
5. 如果是大额误差，可能是代码 bug，需要调试

## 总结

通过以上多层验证机制，我们可以确保：

1. **计算准确性**：所有账户和盈亏计算都经过验证
2. **数据一致性**：交易记录与账户状态保持一致
3. **逻辑正确性**：资金流动符合交易逻辑
4. **可追溯性**：可以手工验证任何一笔交易

当所有验证都通过时，测试结果是可信的，可以用于评估策略性能。
