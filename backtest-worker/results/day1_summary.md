## 关键发现

### 🔍 问题根源分析

#### 1. 数据加载方式的问题

**当前实现（有问题）：**
```python
# 步骤1：DuckDB查询 → 返回所有数据到Pandas DataFrame
df = conn.execute(query).df()  # ← 2.5GB数据全部加载到内存

# 步骤2：传给Backtrader
data = bt.feeds.PandasData(dataname=df)  # df已经占用2.5GB

# 步骤3：设置exactbars
cerebro = bt.Cerebro(exactbars=True, preload=False, runonce=False)
# ← 此时为时已晚，数据已经在内存中了！
```

**内存占用分解：**
```
总内存 = DataFrame占用 + Backtrader内部结构

大数据集（530万条）：
├─ DataFrame：     ~2500 MB  ← 主要占用
├─ Backtrader内部：  ~400 MB
└─ 总计：           ~2900 MB

小数据集（10万条）：
├─ DataFrame：       ~5 MB
├─ Backtrader内部： ~70 MB  ← 主要占用
└─ 总计：           ~75 MB
```

#### 2. Exactbars的限制

**Exactbars只能优化**：
- ✅ Backtrader的内部数据结构
- ✅ 策略的历史访问

**Exactbars无法优化**：
- ❌ 输入数据源（DataFrame）的大小
- ❌ 已经加载到内存的数据

**效果对比：**

| 数据集大小 | DataFrame占比 | Exactbars效果 |
|-----------|--------------|--------------|
| 10万条 | 7% | ✅ 节省44.7% |
| 530万条 | 86% | ❌ 几乎无效 |

### 💡 核心洞察

**为什么小数据集有效，大数据集无效？**

```
小数据集：
DataFrame占用小 → Backtrader内部占比大 → exactbars效果明显

大数据集：
DataFrame占用大 → Backtrader内部占比小 → exactbars效果有限
```

**类比**：
```
房子装修优化：
- 小房子（10万条）：家具占了大部分空间
  → 减少家具（exactbars）→ 效果明显 ✅
  
- 大房子（530万条）：房子本身很大
  → 减少家具（exactbars）→ 效果微小 ❌
  → 需要换小房子（流式加载）✅
```
